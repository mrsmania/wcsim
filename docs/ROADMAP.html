53 Rebuild the versus server, so an invitation says what it is an invitation to Queued 2026-09-01, no migration. A link followed by somebody with no account now shows who opened the room, what it plays and whether a seat is still there. The route that answers it (GET /v1/rooms/:code/invite) is in this repository and not in the container, so until the rebuild the screen falls back to the code alone, which is exactly what it showed before. Rides on the same rebuild as item 52; both are safe in either order. Versus ▸

What it is fixing. A room needs an account, so a link somebody was sent lands on a sign-in screen rather than in the room. That screen could say nothing at all about what had been followed: not who sent it, not what the game was, not whether the seat was still free. Every read of a room needs a session, and a private room answers "no room with that code" to anybody without a seat, deliberately, so a code cannot be confirmed by probing. So the most motivated arrival in the whole product was told the least, and the answer was a route rather than better copy.

What it answers. The host's name, what the room plays (the same sentence the public list writes, minus the pick clock for a duel, which has none), how many seats are left, and whether it has started. Nothing from inside the room: no member row, no XI, no formation, which P19 keeps out of a lobby's reach for the same reason. The checks assert the answer's key set as a whole, so a field added to it later fails there rather than shipping to every stranger holding a link.

The one thing being traded, knowingly. Anybody holding a code can now learn a display name without an account. A code is a secret its host hands out, which is only true at a limited rate, so the route is metered: 20 reads a caller and 240 in total a minute. Six characters from a 31-letter alphabet is 887 million codes, which is minutes of scripting unmetered and years at those figures. A refusal costs the shared budget nothing, so one caller hammering their own limit cannot lock everybody else out.

How to verify after rebuilding - do this, do not assume:

  1. scripts/deploy-referee.sh --verify. Its new step 6 reads the invitation for the private room it just created, with no token at all, and expects the host name back. no-such-route there means the image is older than this repository; unauthorized means something in front of the referee is demanding a token on the one route that takes none, which is the reverse proxy rather than the referee.
  2. Open a private room on one account, copy the link, and open it in a browser that is signed out. It should name the host, say what the room plays and count the seats left, and the button should read "Sign in and take your seat".
  3. Do the same with a duel: it should say who challenged you and that nobody has taken it up yet.
  4. Fill the room and open the link again: the seat count should say so and the button should drop back to "Sign in".
  5. Sign in from that screen. The dialog reloads the page, which lands back on the room's own address, and the seat is taken on arrival.
  6. Check the firewall afterwards. The docker bridge rules have been wiped by the container operations of a deploy before, which takes the whole accounts stack with it (docs/nas-setup.md).

Order does not matter, in either direction. Nothing the referee writes changed and no column moved. The client is already live and treats a missing route, an unreachable server, a closed room and a rate-limited read identically: no answer means the screen shows the code and says why there is nothing else, which is what it did before this existed.

52 Rebuild the versus server, so walking away from a duel costs it Queued 2026-09-01, no migration. A duel abandoned mid-draft now resolves against whoever never sent a team, instead of closing a week later with no result for anybody. The rule is read by the SWEEPER, so it does nothing at all until the container is rebuilt. The client half is already live and degrades to saying nothing, which is correct while there is no window to warn about. Versus ▸

What it is fixing. Reported from the game in one sentence: "leaving a room during rolling does not cost a loss - I can leave the draw without catching a loss." True, and only of the BUTTON. Giving a duel up is a forfeit and the confirm line says so, but leaving the way you leave any other screen - the crest, the Versus tab, Back, closing the tab - sends nothing at all. A duel has no pick clock, no liveness sweep and no lobby close on purpose, so nothing was left to force the issue: the room stopped dead, went on telling both players it was somebody's turn, and a week later closed itself with no result for either side. Which is the free re-roll the lobby and the forfeit were added to shut off, reachable by pressing nothing.

What changed. The week that was already there (DUEL_IDLE_MS) now resolves honestly. Mid-draft, whoever never sent a team loses it, by the same encoding a walked-out duel uses - a champion with no match under it, which migration 0024 already counts, so there is no SQL to apply. Both late still closes it with nobody winning; both teams in still plays the football, however late the sweep. Both draft panels and the wait after sending now name the window.

Not a new deadline, deliberately. A shorter clock of its own was the first shape and it was wrong: the checks draft a duel over nine days on purpose, because playing at your own pace over a week is the mode rather than a tolerance. A two-day window would have halved what a duel may take, which is a separate decision and one constant away if it is wanted.

A neighbouring bug went with it. recoverFromOutage returned a clone for any drafting room even with no windows to hand time back to, and a clone is what the sweeper reads as "this room changed" - so it wrote the room and stamped touched_at. Every sweeper restart would have handed the player who walked away another seven days, for ever. A duel loses nothing to an outage, so it is now skipped outright.

How to verify after rebuilding - do this, do not assume:

  1. scripts/deploy-referee.sh --verify, which mints a session on the box and creates, changes and deletes a real room. A version endpoint answering is not a working referee.
  2. Open a duel from two accounts, both ready, send ONE team, and leave the other alone. Inside the week the row stays under "On now" and nothing moves.
  3. The draft screen names the window: "N days left to send your team, or you lose the duel." An older container sends no such field and the line is simply absent, which is how to tell the two apart from the outside.
  4. Past the week the room ends with the sender as champion and no match under it, and both records move - the loser's row reads as a loss under "Played".
  5. Check the firewall afterwards. The docker bridge rules have been wiped by the container operations of a deploy before, which takes the whole accounts stack with it (docs/nas-setup.md).

Order does not matter in either direction, unusually. Nothing the referee writes changed and no column moved, so the client can ship first (it says nothing without the field) and the container can ship first (the rule simply starts working). There is no migration to sequence against.

The ratings were authored adversarially, and that is the part worth copying. 44 Versus: hand back the time, and move a player in a roll room Half of this shipped on 2026-08-30 and the item shrank rather than closing. Move - dragging a placed man to another of his positions - is now live in buy-them rooms, because those submit the whole team sheet at once and moving is just a different team sheet (item 47). What is left needs the match server to understand an instruction it has not got: Skip, letting a player who has decided end their own pick window instead of watching the clock run down, which matters most in a room of eight where every one of eleven rounds waits for the slowest person; and Move in a roll-for-them room, which still drafts a pick at a time. Needs the versus server changed and redeployed, so it needs the NAS. Versus ▸

What already changed, and why it did not close this. A buy-them room stopped drafting a pick at a time on 2026-08-30: it sends the whole team sheet, so moving a player and taking one back out are the same instruction as buying one and needed no new rule at all. That is Move delivered, for that half of the game. A roll-for-them room still deals a squad per window and still submits one pick at a time, which is right - there the eleven decisions really are separate - so both gestures below still want a server that can hear them.

Why the two that are left are one item. A per-pick draft’s whole instruction set is "here is my pick" and "deal me another squad". Skip has to close the window that is open and start the next one; Move has to rewrite which player stands in which slot. Neither is expressible as a pick, so both are a change to the server and a deploy, which is why neither fitted inside a wave of screen work. Doing them together is one deploy rather than two.

Why the move gesture is OFF rather than half-working. The board is optimistic: a tap places the player at once and the server’s next answer reconciles it. So a move with no instruction behind it would appear to work and then silently undo itself a second later, which is worse than not offering it, and that is the only reason the control is in the room’s off list. The seam is already right: the server records the CURRENT state of an XI rather than a list of picks, precisely so a rearrangement is expressible when there is something to express it with.

What Skip is worth, and the one thing to be careful about. A room of eight finishes its draft when the slowest of eight people finishes, eleven times over, and that is the accepted cost of drawing the bracket only once everybody is in. Skip is the release valve. The care needed: it must take the same random pick a timeout takes, at the same price, or it becomes the fast way to a better XI rather than a way to give time back. Note the measured oddity that makes this worth thinking about - timing out is not uniformly expensive, because a random attacker is nearly the player you would have bought while a random defender is sixteen rating points short, so a Skip is cheap in seven slots and dear in four. That asymmetry is written up in the plan.

How to know it worked. Skip: in a room of two, press it and the next window opens at once for both players, with the skipped slot filled by a random eligible player and the pick marked automatic, exactly as a timeout is. Pressing it twice in one window does nothing the second time. Move: place a player who can fill two positions, move him, and he stays moved after the next answer from the server rather than springing back. Neither may touch anybody’s saved game or Cup Run, which is the standing rule for every room.

If it goes wrong. Both are additive: the previous server image is the rollback, and the client degrades to what ships today - the clock as the only way a window ends, and no move gesture in a room.

34 Album shop: a second way to earn stickers Buy stickers with Prestige or a currency of its own, so the album has an income that does not depend on a 10% event. What unblocks win-only earning. Album ▸

The idea (2026-08-24): let the player spend on stickers - Prestige, or a currency the album earns for itself - instead of only receiving them at the end of a run. High level for now; the shape is not settled.

Why it exists, which is the part worth keeping. It came out of trying FEATURES.stickersOnCupWinOnly both ways on the same day. Win-only is the better meaning: an album that records what you won is a trophy shelf, where one that records everyone you ever drafted is a list. But it is not playable on its own. Measured over 400 simulated runs with a $110 XI at Base Ascension: a run wins the cup 10% of the time and exits in the group 30%, so win-only banks about a tenth of the collectibles any-run does. Against 87 collectibles that is not a slow album, it is an unfillable one. So the flag is off, and this item is what would let it go back on.

The two knock-ons to design against, because the album is not self-contained and both work against a slow album:

  • The owned-sticker discount (STICKER_DISCOUNT, 25%) makes the transfer market cheaper as the album grows. A slow album therefore means a weaker economy, which lowers the cup-win rate, which slows the album further - a real feedback loop, mild at 25% but pointing the wrong way.
  • Duplicates fund trades (STICKER_TRADE_COST), and duplicates come from banking. At a tenth the volume TradeModal becomes decorative, so whatever a shop sells has to keep the trade economy alive too - or replace it.

The questions to settle: which currency (Prestige is already spoken for by perk tiers and boost unlocks, and adding a third sink competes with both - a currency of the album's own avoids that but is one more thing to explain); whether you buy a NAMED sticker or a random one from a tier (named is a shop, random is a pack, and packs interact with duplicates and trades in a way a shop does not); whether prices follow the tier (Monumental dearer) or the player's rating; whether the cup-win reward pick survives alongside it; and whether buying should be capped per run, so a shop cannot short-circuit an album that is meant to take a while.

Not to be confused with the transfer market, which spends a per-run budget on players for one XI. This spends a persistent currency on stickers for the collection. The only place they meet is the discount above.

What it is. Two to eight signed-in players, all present at once, draft a team on the spot and play a knockout. A room is public (listed in a lobby) or private (code only). The host sets the rules and those rules are the feature: roll or budget, how much money, which World Cups, how long a pick gets (20 or 30 seconds), and, in a roll room, whether ratings are visible. What the review changed. Chemistry is now OFF in a room: measured, the same eleven players with the full bonus beat themselves without it 73.2% of the time, because it is added to attack and defence alike and both are what the sim reads. In single-player that is a nudge helping a patchwork XI close on a real national side; in a room both sides are patchwork, so it became the whole game, and a pure knowledge check at that (400 naively auto-filled XIs never once reached the cap). A room gets its own build state, which is a requirement rather than a preference: the app holds one game state and every path that starts a build clears the active run, so a room entering through the same door would have silently deleted a live Cup Run, and while signed in every single tap writes to the server, where one failure raises the blocking unreachable screen with the pick clock still running. The referee holds no timers (a stored deadline and a stateless sweeper, which is restart-correct by construction), and it must give back the time an outage ate or a thirty-second container restart auto-picks for every player in every drafting room at once. And the build order is now a vertical slice: a private two-player room playable end to end at wave 5, instead of the first complete game arriving at wave 7 behind an optional polish wave.

One thing accepted with its numbers, by decision. The sim reads two numbers a side, so the budget draft has a closed-form best answer: defence averages over fewer slots, so it is cheaper to lift, and only two formation families field four defensive slots. Measured at $110, a stacked 3-4-3 beats an even 4-3-3 56.6% - and when both finalists have found it the match measures 0.62 goals and 54.4% decided on penalties, against 2.35 goals and 16.9% for two even sides. That empties the live goal feed, which is the mode’s flagship screen. Kept as skill rather than designed against; turning chemistry off sharpens it, since chemistry was the one axis competing with it. The cheapest reversal, a minimum spend per line, is one rule in wave 0 and nowhere else.

Two corrections to this plan’s own earlier text, both found by review and confirmed in the code: the knockout resolver was said to need lifting out of the Cup Run and is already exported and shared, so that wave-0 item is gone (what is actually needed is a two-sided team builder, since the existing one hard-codes “Your XI” and cannot describe two opponents); and a roll deal was said to guarantee a squad that can fill an open slot, where the code only prefers one and falls back to the whole pool.

Two late additions, 2026-08-26. In a room of more than two, every draft finishes before anything is paired, and then the whole bracket is drawn at random in one go. 1. Full-Backs is dead in a quarter of the formations. Three ways out, and none is obviously right: (a) widen the target to the two widest players in the defensive line, so a back three's outside centre-backs qualify - keeps the card alive everywhere but blurs what it says; (b) retarget to the flanks (LB/RB, else LM/RM as wing-backs) - true to the football, but it moves +8 onto MIDfielders, which lands in the attack average and needs re-banding; (c) leave it and accept that one card rewards a back four, which is a legitimate build-shapes-matter choice as long as it is deliberate rather than an accident of a wrong comment. 2. A card already taken can be taken again.   • It stacks, sometimes multiplicatively. Sponsorship twice is xpMult 2 then 4, so 4x XP; Ice Veins twice is +16 to the penalty takers; Golden Generation twice is +4/+4. A player who is offered Sponsorship twice should obviously take it twice, which is a lever no card was priced against.

  • Or it is fine. A second Poach or Wildcard Legend is another player, which is a real choice and arguably the interesting case.
So "exclude what the run already holds" is the obvious fix and it would remove the third case along with the first two. The alternative is to exclude only the cards that cannot benefit (the idempotent ones) and price the stacking deliberately.
