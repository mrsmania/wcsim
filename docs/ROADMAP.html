01 Challenges / Mandates Something to aim at in Career Mode, instead of Prestige just piling up. Career ▸

The highest-value gap. The career layer has no goals: you play, you earn Prestige, you buy perks, and that is the entire loop. Challenges give a reason to attempt a particular kind of run rather than the same strongest one.

  • Renewable objectives checked against the finished RunState: win at Ascension III, win with an XI averaging under 80, clean-sheet the knockouts, win with a single-nation XI.
  • They pay in Prestige and in trophy-cabinet entries, which is also what would give the cabinet (item 06) something to hold.
  • Data model and example challenges already drafted in docs/career-depth-spec.md, "Future ideas / E".
  • Pairs well with accounts: progress is per account, so it follows you between devices.

Decision first: are challenges permanent, rotating, or a mix? Then pick the opening handful.

Players whose sticker you already own should be cheaper in the transfer market, so the album pays back into the game. A constant in src/config.ts is fine for x; no UI needed.

03 More World Cups and collectibles Extend the dataset backwards from 1990: 1986, 1982, and earlier. Content ▸

The dataset covers 1990 to 2022, all nine fully researched. Collectibles grow for free, since collectibility is derived from rating via STICKER_TIERS.

  • Method notes from the 1990-2002 round apply: identical name spellings across tournaments for the same person (personId is the name slug), distinct people must have distinct names, ratings are that-tournament strength on 60-99.
  • Field sizes shrink going back (24 teams in 1982 and 1986, 16 in 1970-1978), so check the group draw and any "32 nations" assumptions first.
  • Period identities keep their own codes, as Soviet Union, Czechoslovakia and Yugoslavia already do.
  • Remember the server: after any rating change run npm run gen:collectibles then npm run push:collectibles. npm run checks fails while the seed is stale.

Next step: do 1986 end to end as the template for the rest.

07 Apply the Supabase trim on the NAS The edits are prepared and checked; someone with LAN access has to install them. Server ▸

The stack still runs storage, imgproxy, realtime and the edge runtime, none of which the game uses, with /storage/v1/ and /functions/v1/ reachable and the bundled example function executing without a JWT. The trimmed files exist and were verified locally (compose resolves to exactly 7 services; all 15 remaining gateway routes point at a cluster that still exists). What is left is installing them, which needs the NAS.

Do this from the laptop that has the repo dkr/ is gitignored, so the edited files exist only in that working copy - they are not on GitHub and not on any other machine. Needs the LAN or the VPN, and SSH on the NAS. Nothing here touches .env or the database; only the gateway restarts.
  1. Confirm the NAS copy is the one that was edited. The .bak files are the pre-edit originals, so they are what the NAS should match. In the repo: 
    md5sum dkr/docker-compose.yml.bak
md5sum dkr/volumes/api/envoy/cds.yaml.bak
md5sum dkr/volumes/api/envoy/lds.template.yaml.bak
    and on the NAS, in the folder the Container Manager project points at (per docs/nas-setup.md, something like /volume1/docker/wcsim-supabase): 
    md5sum docker-compose.yml
md5sum volumes/api/envoy/cds.yaml
md5sum volumes/api/envoy/lds.template.yaml
    All three match, carry on. Any of them differs, stop: the NAS copy drifted during setup, so send that file over and have the deletions re-applied on top of it rather than overwriting whatever was changed.
  2. Back up on the NAS anyway. Cheap, and it is the rollback: 
    cp docker-compose.yml docker-compose.yml.pre-trim
cp volumes/api/envoy/cds.yaml volumes/api/envoy/cds.yaml.pre-trim
cp volumes/api/envoy/lds.template.yaml volumes/api/envoy/lds.template.yaml.pre-trim
  3. Copy the three edited files up (File Station, a mapped drive, or scp). The plain names, not the .bak ones: 
    scp dkr/docker-compose.yml USER@NAS:PROJECT/
cd dkr/volumes/api/envoy
scp cds.yaml lds.template.yaml USER@NAS:PROJECT/volumes/api/envoy/
  4. Apply it, on the NAS in the project folder: 
    sudo docker compose up -d --remove-orphans
    --remove-orphans is the part that actually deletes the four containers the compose file no longer mentions. Container Manager's Project → Action → Build works too but does not pass that flag, so if you go through the GUI, delete these four by hand afterwards in the Container tab: supabase-storage, supabase-imgproxy, realtime-dev.supabase-realtime, supabase-edge-functions.
  5. Verify. The first two must still answer 200, the last two must no longer be served by a storage or edge-runtime container: 
    sudo docker compose ps
  # 7 services: db, auth, rest, api-gw, studio, meta, supavisor

curl -s -o /dev/null -w '%{http_code}
' https://HOST/auth/v1/health
curl -s -o /dev/null -w '%{http_code}
' -H "apikey: ANON_KEY" https://HOST/rest/v1/
curl -s -o /dev/null -w '%{http_code}
' https://HOST/storage/v1/status
curl -s -o /dev/null -w '%{http_code}
' https://HOST/functions/v1/hello
    The last two now answer 401, because those paths fall through to the catch-all Studio route and Studio sits behind basic auth. That is the expected result: the point is that there is nothing behind them any more. Then in the browser, sign in on the deployed game, open the album and finish a run - album, career and run state all go through /rest/v1/, which is untouched.
  6. If anything is off, roll back and nothing is lost: 
    cp docker-compose.yml.pre-trim docker-compose.yml
cp volumes/api/envoy/cds.yaml.pre-trim volumes/api/envoy/cds.yaml
cp volumes/api/envoy/lds.template.yaml.pre-trim volumes/api/envoy/lds.template.yaml
sudo docker compose up -d
sudo docker compose restart api-gw   # envoy re-reads its config files

Meanwhile: if you want the exposure gone before you are back at the laptop, stop those four containers in Container Manager - a minute's work from anywhere, including the phone. A project rebuild brings them back, so it is a stopgap, not the fix.

Guest only, and the snippet says so.
