01 Challenges / Mandates Something to aim at in Career Mode, instead of Prestige just piling up. Career ▸

The highest-value gap. The career layer has no goals: you play, you earn Prestige, you buy perks, and that is the entire loop. Challenges give a reason to attempt a particular kind of run rather than the same strongest one.

  • Renewable objectives checked against the finished RunState: win at Ascension III, win with an XI averaging under 80, clean-sheet the knockouts, win with a single-nation XI.
  • They pay in Prestige and in trophy-cabinet entries, which is also what would give the cabinet (item 06) something to hold.
  • Data model and example challenges already drafted in docs/career-depth-spec.md, "Future ideas / E".
  • Pairs well with accounts: progress is per account, so it follows you between devices.

Decision first: are challenges permanent, rotating, or a mix? Then pick the opening handful.

03 More World Cups and collectibles Extend the dataset backwards from 1990: 1986, 1982, and earlier. Content ▸

The dataset covers 1990 to 2022, all nine fully researched. Collectibles grow for free, since collectibility is derived from rating via STICKER_TIERS.

  • Method notes from the 1990-2002 round apply: identical name spellings across tournaments for the same person (personId is the name slug), distinct people must have distinct names, ratings are that-tournament strength on 60-99.
  • Field sizes shrink going back (24 teams in 1982 and 1986, 16 in 1970-1978), so check the group draw and any "32 nations" assumptions first.
  • Period identities keep their own codes, as Soviet Union, Czechoslovakia and Yugoslavia already do.
  • Remember the server: after any rating change run npm run gen:collectibles then npm run push:collectibles. npm run checks fails while the seed is stale.

Next step: do 1986 end to end as the template for the rest.

08 Saving new stickers takes 1-2 seconds Signed in, the run-end haul waits on the server. Perf ▸

Banking a finished run takes up to a second or two before the summary appears. The path is applyStickers to the store's finishRun to the finish_run Postgres function, with writes serialized in remoteStore and a 4s release timer (BANK_WAIT_MS) as the backstop that stops a slow server from blocking play.

Measure before changing anything: the time could be the NAS round trip, the write queue, the function itself, or simply that deliberate wait. Each has a different fix, and one of them is not a bug at all.

Next step: use a specialized agent to profile it end to end, then choose between an optimistic summary, a leaner RPC, or overlapping the write with the reward pick.

10 Move a placed player within his position range Click his circle on the pitch to shift him to another of his roles. Feature ▸

Once a player is in the XI his slot is fixed: the only way to move him is to remove him and place him again. Clicking his badge should offer the other slots his positions allow, taking an empty one or trading places with whoever is there.

Mind one trap: placedPlayers reorders a player's positions so the slot he filled leads, because downstream code keys off positions[0]. The move has to read his dataset positions, not the reordered copy, or his range shrinks with every move.

15 Rework the sign-in email, with a copy button Make the six-digit code easy to lift out. Accounts ▸

The mail GoTrue sends is still its stock template. It should look like the game and make the code trivial to get at, especially on a phone.

Next step: worth knowing before designing it - mail clients do not run JavaScript, so a real copy button inside the email is not possible. The workable versions are a large, letter-spaced, selectable code (tap-and-hold copies it on phones), or a link back to the game carrying the code so the field fills itself in. The template lives in GoTrue's mailer config on the NAS, not in this repo, so shipping it is a server-side change.
