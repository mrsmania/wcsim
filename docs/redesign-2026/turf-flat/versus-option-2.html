Versus: act on the left, watch on the right

Option 2 of the five, elaborated. Two columns that never swap: everything you do is on the left, everything that is happening is on the right, so your own history can never push the form below the fold however long it gets. Seven chip rows become two big choices and three named accordions, each showing its own answer while it is shut.

Three corrections from the sketch. a. On a phone it uses option 1's order, not a hoisted alert: start, join, lobby, waiting, results. The chrome already carries a duel strip on every screen in the game, so the page does not have to shout as well. b. The seat bubbles sit between the room title and the button, which gives the list three columns of matching width instead of a different shape at the start of every row. c. A played match carries no room code. A code is how you reach a room, and a finished one is not going anywhere.

2The accordions, and what is inside each

Three, never more, and which three depends on the pace, which is the field dependency doing the work. A challenge gets two; a live room gets three. Each one shows its own answer on the right while it is shut, so nothing is hidden, only folded. They open independently: shutting one somebody deliberately opened reads as a fight.

3The live room, shut

Choosing "Together, now" adds one accordion and changes what is inside another. Nothing else on the page moves, and the button changes its word.

The order, and why
  1. Start a match. The thing the page is for.
  2. Join with a code. Beside it, because it is the same intention arriving from the other direction.
  3. Rooms open now. The half of the mode that depends on other people, and the one that goes stale, so it wants to be seen.
  4. Waiting on you. Below the lobby rather than above it, which is the correction: the chrome carries a duel strip on every screen in the game, so somebody with a match waiting has already been told before they got here.
  5. Your results. Last. It is a record, and a record is something you go looking for.

Two rows of the lobby and two of each list on a phone, with the rest behind the "All 4 results" line. The seat bubbles keep their fixed slot but drop the minimum width, so a room of eight wraps its button to a second line instead of squeezing the name.

8What it costs, and one thing found on the way

  • No server work, no migration and no protocol change. Every setting still reaches the same create call with the same values, and the lobby and duel reads are untouched.
  • The two lists and their copy helpers stay exactly as they are. What changes is the page around them, the row's three columns, and dropping the code from a finished one.
  • The seat bubbles need the practice-opponent count, which the lobby row already carries, and read as zero from an older server, which draws them as free chairs. That is the correct fallback: a stranger's room with unknown chairs is a room you can try to sit in.
  • Three accordions is three pieces of state and three sets of summary copy, which is the real work: the summary has to stay true for every combination, since it is the only thing standing between a folded setting and a hidden one.
A small bug the elaboration turned up, and it is not this one's to fix. The lobby row prints "20s a pick" for a room that buys, and a buying room has run one clock over the whole draft since the whole-draft change: it does not hand out per-pick windows at all. So a stranger reading the list is told the wrong clock, and the right one cannot be printed because the public row does not carry it. The mock above writes what it ought to say ("Buy an XI with $150, 5 min to draft"); making that true needs the draft length added to the public row, which is one field on the wire and a referee rebuild. Worth its own roadmap item rather than smuggling into this.
