Works, but adds a control

Two views of the same progress

A segmented control at the top of the run swaps the compact ladder for the full tree. The ladder stays the phone default; the bracket is the wide view. It reads well as an idea - and the drawing is what shows the problem: the run screen now has two things that both answer "where am I", and the navigation audit already flagged a second stepper on this screen as something needing reconciling.

What the drawing exposes. With the bracket on, the ladder is gone - and with it the review affordance, which is the ladder's other job: clicking a past step opens that round's read-only recap. So the toggle does not swap two views of one thing; it swaps a control for a picture. Either the bracket learns to be clickable per node (which is option A with extra steps) or you lose review while looking at the tree.

What it buys

  • The phone keeps the compact view by default, and the tree is opt-in where there is width for it.
  • Nothing about the run flow changes - the toggle is additive, so it is easy to ship and easy to remove.

What it costs

  • A second progress control on one screen, which is precisely what the navigation audit said needed reconciling rather than duplicating.
  • A state to remember: which view you last used, per run or per device - another small preference nobody asked for.
  • You still never play on the tree.
