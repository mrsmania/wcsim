Asked 2026-08-21

One-off goes. Its two best screens move in.

4 options · 1 settled
Built · option A · 2026-08-21 Decided and shipped, for the five-tab chrome only. The group opens with the draw and a table that fills in as the matchdays reveal; the knockouts run on a real 16-team bracket, collapsed to your own path with the full draw behind a chevron - the tree was too tall to sit above every screen of a run, which the option A page did not foresee. Two more things changed on playing it: Ascension is picked on the build page (so the pre-run screen is gone and "start run" goes straight into the draw), and the run ladder went, because the table and the tree were already saying it. Both traps the facts table below names were real: buildBracket needed the Ascension slope threaded in, and the live table needed groupAsOf. What did NOT ship is the one item here that was never chrome - one run at a time. See CLAUDE.md for the shipped detail and roadmap item 28 for what is left.

Two decisions, and they are not the same size. Dropping One-off from the tabs navigation is settled and small. Bringing the group draw and the knockout bracket into a career run is the work: the group half is specified below, and the bracket half has four candidate homes, one page each. Read the facts first - two of them decide most of it.

The facts, read in the code

WhatState todayWhat it means here
The group is already fully simulated prepareGroupStage (domain/run.ts) plays all three matchdays up front and returns the whole Group - every fixture, every result, the other two teams' games included - plus the user's three matches. A live, matchday-by-matchday reveal needs no new simulation, only a projection of the group "as of matchday N".
The draw modal is already generic GroupDrawReveal takes { userTeam, opponents, onContinue } and nothing else. It scrambles flags, settles, and respects reduced motion. Reusable as is. Nothing to fork.
The standings table is already shared StandingsTable takes { group, groupFinished, advanced }, and the Cup Run's group-results screen already renders it - just once, at the end. Showing it earlier, updating per matchday, is the same component with a different group value.
The bracket renderer is pure <Bracket bracket={...} /> - one prop, a BracketState. It draws the wide left-to-right tree and the two-sided phone tree, and crowns the champion. Whatever we decide, the view costs nothing. The question is only where it sits and what feeds it.
A Cup Run has no bracket at all The knockout draws one opponent per round: drawOpponent(faced, pool, asc.drawSlopeBonus), with koRound 0 to 4. There is no field of 16, no other ties, nothing for a tree to show. This is the real work. The view is free; the data is not.
But building one is nearly free buildBracket(user, coQualifier, excludeIds, pool) already seeds a 16-team field with the user at seed 0 and the co-qualifier in the opposite half, and bracketSeedFromGroup(group) already derives its three arguments from a finished group. The Cup Run can call the same two functions it already has in the building.
The one snag in that last row. buildBracket fills its 14 open seeds with drawOpponent(faced, pool) and passes no slope, so it always draws at the default weighting. Ascension's whole second lever is drawSlopeBonus - a steeper draw toward stronger squads - so it needs one optional parameter threaded through, or Ascension III would field the same opponents as Base. Small, but it is exactly the kind of thing that goes unnoticed until someone wonders why the higher tiers feel easy.

Settled: dropping One-off

What goes

  • The Career run / One-off control in SetupPanel, and with it the runKind state in App. Every run in the tabs chrome is a career run.
  • The build page's mode branch: CompletePanel's CTA always leads to /cup-run, and the two Career-Mode perks (transfer budget, extra re-roll) always apply.

What it decides by deletion

  • "Should a one-off pay?" - the question the nav audit deliberately left open. There is no one-off, so it pays nothing by not existing.
  • /group and /knockout become classic-chrome only. The World Cup engine is still there and still reachable at ?nav=classic; nothing is deleted yet.
And it points somewhere. A Cup Run with a real 16-team bracket, at Base Ascension with no boost taken, is a World Cup. That is the "a Cup Run is a superset" argument from the navigation audit, and it turns the two tournament engines from a duplication nobody owns into something with an obvious end state. Not this change - but this change is the step that makes it possible.

Exactly as asked: Play group stage opens the draw animation, and behind it the group table and the three matchdays reveal one at a time, with the table updating as they land - the World Cup group screen, inside the run. Drawn on its own page: the group stage →

Recommended

The bracket is the stage, because that is the screen you liked

  • It is the thing itself. What is good about the World Cup knockout screen is not the tree as a picture - it is playing your tie on the tree, with the rest of the round filling in around you. B, C and D all show you a tree; only A gives you that.
  • It adds no mechanism. The ladder stays the one progress view and keeps its review role; no toggle, no seventh overlay. The tree is content, not chrome - which is also why it does not reopen anything the navigation rework settled.
  • It makes the run read as a tournament rather than as five ties in a row, which is the same instinct behind roadmap item 04's node variety: the gap between rounds should feel like part of a competition.
  • The cost is honest and bounded: RunState gains an optional bracket, the per-round drawOpponent becomes currentGame(bracket), and the content area gets taller - on a phone noticeably, which is what the two-sided tree already exists for.
If the appetite is smaller, B is the honest fallback and it upgrades into A later without rework: the same BracketState, the same renderer, moved from "after the tie" to "the tie is played on it".

What every option shares

  • One new pure helper, whatever we pick: a group projection ("as of matchday N") so StandingsTable can be fed a partial group without re-simulating one. Belongs in domain/tournament.ts beside standings.
  • Two new run phases at most. RunPhase is 'group' | 'boon' | 'match' | 'ended' today; a revealed group needs the group step to be enterable and dismissable, which is reveal state rather than a phase - the same distinction the run already makes for its live match.
  • Persistence is safe by precedent. RunState.shape, .build and .chemistry are all optional so a run saved before them resumes; .bracket follows the same rule, and a run mid-flight when this ships simply finishes on the old one-opponent draw.
  • The checks harness has to grow with it: a bracket in a run must still crown exactly one champion, and the user's own tie must be the one they played - both are already asserted for the World Cup bracket, so the assertions are copyable.
