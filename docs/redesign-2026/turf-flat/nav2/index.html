Concept 2, drawn at scale

Five tabs, and what they cost

10 pages · one stylesheet
Built · 2026-08-21 This is no longer a proposal. Concept 2 is implemented and live behind ?nav=tabs (src/nav/navMode.ts), with the classic chrome still the default, so the two can be compared in one build on the same progress and the same account. Everything on these pages shipped: the kept cover, the run-kind control, the split career route, the segmented Records tab, the bar going inert during a match reveal and the phone's pitch-first build page - though that last one was reverted on 2026-08-21, see decision D below. What did NOT ship is the one item here that was never chrome - one run at a time. The cover picks a single Continue by priority and "build a new XI" resets, so it reads as one run, but two can still be live. See CLAUDE.md for the shipped detail and roadmap item 27 for what is left.

The five candidate models are compared in ../nav-options.html. This set takes the recommended one and draws it at full scale on ten screens, because a nav model is easy to like as a diagram and hard to like once a 130-row ledger, a three-column build page and a live match are inside it. Every screen body is the shipped layout. Nothing here adds, removes or moves a feature.

The pages

  • Home - the front page, kept. One Continue action, the career headline, and what "build a new XI" now costs. Revised 2026-08-21.
  • Play: set up - formation, style and the Career run / One-off control. No resume list: the cover has it.
  • Play: build - mid-draft with a rolled squad. The screen that rules out the rail.
  • Play: market - the same page with the transfer market in column one.
  • Play: Cup Run - a live tie with the bar locked, then the boost pick with it live again.
  • Career - the hub, no longer sharing a route with the run.
  • Album - unchanged screen, promoted from a card in a build column.
  • Records - Challenges and Cabinet as two segments. The fix for the four-click catalogue.
  • Squads - the read-only archive, the fifth tab.
  • Phone - four device frames, including the pitch-first build order. The page to read second.

What this set commits to

Four of these are not choices: all five concepts arrived at them independently, so they are decisions whichever model wins. The last three are what makes this concept 2 rather than the schematic in ../nav-2-tabs.html.

A The two launcher doors go Mode becomes a "Career run / One-off" control on the build page, beside formation and style. One-off keeps today's Quick Run reward rules exactly. Deletes finding F3. agreed
B The career hub and the live run split routes A shop and a step of play cannot be the same address. CareerHub is already its own file, so this is a move, not a rewrite. agreed
C The two nav cards leave the build column Album and career stop being cards inside content, one of them conditional on a sub-view. They are tabs. agreed
D The phone build page goes pitch first — REVERTED Pitch, then the source panel, then ratings collapsed to a bar. Independent of the nav model, so it is work either way. Built, then reverted on 2026-08-21: the sandwich this was meant to fix was already solved by motion, not by order - picking a player scrolls the pitch up, placing him scrolls the panel back - and pitch-first breaks that pairing, because scrolling to a pitch already at the top does nothing and the return scroll then travels the wrong way. The one of the four that did not survive contact. agreed
1 The tab row carries the masthead rule The tabs sit inside the identity block rather than as a strip below it, which is the answer to "a top tab bar reads as a sub-nav". Plus a route crumb under it, so "where am I" has two signals. added
2 The bar is inert while a match reveals The one thing a tab can lose that a drawer cannot. Same locked flag the run ladder already takes. Everything else about leaving and returning is lossless, because progress is reducer state mirrored to storage. added
4 The cover stays, and holds one run Decision A deletes the two mode DOORS, not the launcher screen, which concept 2's own schematic always had. Paired with one run at a time, so the cover carries a single Continue instead of up to three resume rows. The one-run rule is functionality rather than chrome - see Home for what it changes. added
3 Optional counters in the tab sub-line 34/81, 41/130, Lv 7. The dashboard concept's one real advantage, imported at zero horizontal cost. First thing to cut if the bar feels busy. added

Correcting the concept's own cost list ../nav-2-tabs.html says a bottom bar competes with the run-end summary and reward picker "both of which are bottom-anchored today". They are not: Overlay.tsx is fixed inset-0 z-[80] grid place-items-center over a full-screen backdrop, and the group draw is a separate centred z-40. So this is one z-index line, not a design conflict. Finding F9 (six overlays) is left for its own pass either way.

What this set does not decide

  • Whether a one-off run pays. XP, Prestige and the 98 challenges a World Cup could judge. That is functionality, it has no roadmap item since 22 was dropped, and the mode switch is neutral on it.
  • Whether the two tournament engines converge. The thing that would make One-off one code path instead of two. Unowned, and not behaviour-preserving, so not the hygiene backlog's either.
  • The overlay pile (F9). Reduced by nothing here; the bar just stays under it.
  • Dark theme. These comps are light only. The shipped tokens cover both.

Chrome it touches

src/App.tsx (masthead, footer nav, route branch), src/components/ModeSelect.tsx (deleted), the two in-column entry cards in App.tsx, src/components/cupRun/CareerHub.tsx (split from the run screen), SettingsModal.tsx and AccountModal.tsx. No domain/, no state/, no reducer action, no feature flag, which is what makes item 27 safe to land ahead of items 23, 04, 05 and 19.
