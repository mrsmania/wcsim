Five navigation reworks, one decision

The click paths are the problem, not the features

The briefKeep every feature exactly as it is. Rework the UI and the click paths, which have grown six separate navigation mechanisms, none of which can reach everything, and a 130-entry catalogue that is four taps in behind a collapsed panel.

What is actually wrong read in the code, not remembered

Ten findings. Each is a navigation or layout fact, with the file that proves it. None of them is a missing feature, and none of the five concepts adds or removes one.

F1

Six navigation mechanisms, none of them complete

The crest links home; a footer text nav lists four of the eleven destinations; the launcher has two door cards plus up to three resume buttons; the build page has two entry cards inside a content column; the career hub has the only links to /challenges and a second one to /cabinet; the tournament screens have their own crumbs. Six systems, and no single one of them can reach everything.

F2

Challenges is four clicks in, behind a collapsed panel

The only door is inside CareerHub (cupRun/CareerHub.tsx:196), which lives on /cup-run, which is reached from a card that only renders on the career build page in the setup sub-view. The hub body also starts collapsed, so the link is not on screen when you arrive. 130 entries and the catalogue is effectively unlisted.

F3

Two doors lead to the same page

/quick-run and /career-mode are the identical 3-column build page. The route only decides what the single Start Run CTA does (App.tsx:647) and two perk values. The player is asked to choose before they have anything to choose with.

F4

/cup-run is two screens sharing one route

It is the career hub (perk shop, boost library, challenges, trophies) AND the live run. During a run the hub collapses to a strip with a chevron, so a shop is also a header. A destination and a step of play cannot be the same address.

F5

Navigation lives inside a content column

The album card and the "Cup Run career" card are the first two things in the build page's left column (App.tsx:947, 978), above the setup panel. The second is conditional on mode === 'career' && homeView === 'setup', so it disappears the moment you place a player.

F6

One column is four different things

The left column is SetupPanel, then SquadPanel or BudgetMarket, then CompletePanel, plus the two nav cards. It has no stable identity, so nothing on the page tells you what that region is for.

F7

There is no persistent "where am I"

The only global location signal is the active colour on the footer nav: 11px mono, below the fold. The build page has a phase eyebrow, the tournament screens have a crumb, and the rest have nothing.

F8

Reset and back land in inconsistent places

handleReset returns to the build route matching where it fired, so a World Cup always goes to /quick-run even when the build was a career one (App.tsx:564). Browser Back, the crumbs and the CTAs are three separate answers to "go back".

F9

Six overlays compete for the same space

Settings, Account, the group draw, the cup reward picker, the sticker trade and the run-end summary are all modals; confetti sits above them at z-[90]. Two can be earned in the same moment at the end of a run.

F10

On a phone the pitch is in the middle

The single column stacks source panel, then pitch, then ratings and line-up. The thing you tap is sandwiched between the thing you pick from and the thing you check, so a draft is a scroll up, a tap, a scroll down, repeated eleven times.

The five concepts

Each is a different answer to "what is always on screen". They are drawn over the same thirteen screens, so the comparison is like for like: only the frame and the paths differ.

What all five agree on decide these once, whichever wins

A

The two launcher doors go

Every concept turns the mode into a control on the build page instead of a choice made before you have anything to choose with. That is finding F3, and no nav model survives keeping it.

B

The career hub and the live run stop sharing a route

A shop and a step of play cannot be the same address. Every concept splits them, which is a component move rather than a feature change: CareerHub is already its own file.

C

The two nav cards leave the build page's left column

Navigation that lives inside content, one of it conditional on a sub-view, is finding F5. Wherever the nav ends up, it is not in that column.

D

The build page needs its phone order changed

Pitch first, source panel under it, ratings and line-up collapsed to a bar. Finding F10 is independent of the nav model, so it is work either way, and only concept 5 claims to address it as part of the rework.

Does Quick Run make sense at all? asked directly, answered directly

No, not as a door. Yes, as a switch. The capability is worth keeping and the mode is what has to go, and that turns out to be a navigation change rather than a feature one.

1

The two doors are already the same page

Both cards lead to the identical 3-column build page with both build methods. The route decides what one CTA does (App.tsx:647) and two perk values, the transfer budget (App.tsx:87, 675) and the extra re-rolls (App.tsx:334). That is the whole of the difference at build time.

2

A Cup Run is a superset of a World Cup

They share the match sim, the group build, the draw, resolveKoTie and the live clock. A Cup Run adds boosts and Ascension on top. There is nothing a Quick Run can do that a Cup Run at Base ascension with no boost taken cannot, which makes it a strictly dominated option, and a strictly dominated option on a launcher is a question the player cannot answer.

3

The door is expensive

It buys a second tournament engine, a duplicated round shell, two outcome models, two once-per-run sticker guards, two run-end panels, a chemistry rule that disagrees with itself (by slot in the World Cup, by natural role in a Cup Run), four reachable cross-mode leaks, and a mode derived twice (modeOfPath from the route and buildMode in the reducer, because the route cannot answer where a build started once you have left it).

4

What it genuinely provides, and how to keep it

Two real things: a consequence-free way to learn the draft, and a shorter session with no between-rounds decision. Neither needs a mode. Both are settings on a run: no extras (which Base ascension with boosts off already is) and nothing banked.

The recommendation: keep the capability, drop the door. One entry, one build page, and a two-state control on it, "Career run" or "One-off", sitting next to formation and style where every other build choice already lives. Set it to One-off and the reward rules stay exactly what Quick Run's are today, so nothing is added or removed: stickers bank, the career does not. That is a chrome change, in scope for this rework, and it deletes finding F3 outright.

5

What this deliberately does not decide

Whether a one-off run should pay (XP, Prestige, the 98 challenges a World Cup could judge) is roadmap item 22, and it is a functionality question, not a navigation one. The switch above is neutral on it: item 22 can later change what One-off pays without touching the nav again. Whether the two engines converge is the same, and it is the thing that would let One-off be one code path instead of two.

Reading order

4 is the smallest change and the weakest orientation. 1 and 2 are the same idea at two screen sizes: five destinations, always visible. 3 is the only one that scales past eleven screens without a second thought, which matters because items 04, 05 and 19 each add one. 5 is the only one that treats the run as the spine of the app, and the only one that fixes the build page rather than framing it.

Static comp. No JavaScript, no build step: open it in a browser. Every screen body is the shipped layout, schematic: the rework is the chrome and the paths, so if a body had to change to suit a nav model, the nav model would be changing the app.
