Stage flow and drawers

The nav model, in one sentenceThe tournament is the app: one stage stepper across the top, always showing where you are in the run. Everything else opens as a drawer over it, so you never leave.

How it works

Always visible
The stepper: Setup, Build, Group, Knockout, Result. Plus three drawer buttons (Album, Honours, Squads) and settings.
Where am I
The lit step, which is the only concept where the answer is about the run rather than about the app.
Drawers
Album, Honours (Cabinet and Challenges), Career, Squads and Settings all open as a right-hand panel over the current screen. Closing one returns you exactly where you were.
No destinations
Nothing outside the run is a page you navigate to, so there is nothing to navigate back from. The routes stay, for deep links and refreshes.
Responsive
The stepper compresses to five dots with the current step named. Drawers become full-height sheets.

On a phone the case that matters most

The ten findings what this concept does about each

The audit is on the index page. Here is only what this concept changes, including the ones it leaves alone, which are the honest part.

F1

Six navigation mechanisms, none of them complete

Two mechanisms on purpose, and they answer different questions: the stepper is where you are in the run, the drawers are everything that is not the run.

F2

Challenges is four clicks in, behind a collapsed panel

Two clicks, Honours then Challenges, and the drawer never costs you your place in a match.

F3

Two doors lead to the same page

The doors go. Mode is a Setup-step choice, which is exactly what it is.

F4

/cup-run is two screens sharing one route

The hub becomes a drawer, the run stays a step. They can be open at the same time, which is what a between-rounds perk purchase actually wants.

F5

Navigation lives inside a content column

Both cards become drawer buttons in the masthead.

F6

One column is four different things

Directly addressed, and this is the concept that goes furthest: the column swap becomes the Build step, with the stepper naming it.

F7

There is no persistent "where am I"

The strongest answer for the run and the weakest for the app: the stepper tells you the round, but nothing tells you where the album sits.

F8

Reset and back land in inconsistent places

The stepper makes back explicit and reversible: a finished step is clickable, so there is one way back and it is visible.

F9

Six overlays compete for the same space

Makes it worse before it makes it better. Everything becomes an overlay, so the layering rules have to be real: one drawer at a time, and the earned overlays (reward pick, run-end summary) always win.

F10

On a phone the pitch is in the middle

A drawer is a better phone pattern than a route change, and the stepper is a better phone header than a tab bar. The build page still needs its column order fixed.

What it buys, what it costs

Buys

  • The only concept that treats the run as the spine of the app, which is what the app is.
  • A drawer never loses your place, so checking the album mid-draft or the perk shop between rounds stops being a round trip.
  • It fixes findings F6 and F10 rather than working around them: the stepper gives the build page a named step and the drawers free the columns.
  • Deep links and refreshes still work, because the drawers are routes that render over whatever the run state is.

Costs

  • Piles more onto the overlay problem, and F9 is already a real one. This concept only works if the layering is specified first.
  • Discoverability is by icon. Three unlabelled buttons in a masthead is how the album card ended up in a content column in the first place.
  • A stepper implies a linear run, and the Cup Run ladder is already a second stepper on the same screen. Two steppers need reconciling.
  • The largest UI diff of the five even though no feature moves: every non-play screen has to work as a 420px drawer as well as a page.
