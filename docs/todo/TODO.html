02 Login / user account Persist album, career status, and future challenges across devices. Requirements settled, no open questions. Next: the design doc. Platform ▸

Everything is localStorage today (wcsim_album_v1, wcsim_career_v1, wcsim_run_v1, plus the game key), so a second device starts from zero.

Model decided 2026-08-11 Two separate worlds, never mixed. Guest progress stays in localStorage; account progress lives only in the database. Nothing merges. The one crossing is a single user-confirmed import at first login, and it is a move: local data is deleted once the server write is confirmed, so no stale twin is left behind. Logged in and the server is unreachable means you cannot play: a blocking retry, plus "continue as guest" as the escape hatch. This deletes the hardest problem in the topic (how to reconcile duplicate counts and trade history between two diverged copies) rather than solving it.
  • Guest-first, not offline-first. Nobody is ever forced to sign in, and guest play never touches the server. Signing in buys continuity and backup (same album everywhere) and may gate genuinely online extras such as highscores, but never core gameplay, content, or progression.
  • Stack: self-hosted Supabase on the NAS (Postgres + Auth + PostgREST, trimmed containers, Studio on LAN only). The SPA stays on GitHub Pages: Supabase authenticates with a bearer token rather than a cookie, so two origins is a non-issue and guests keep riding always-up hosting. Hosted Supabase was rejected because free projects auto-pause after a week idle, which under the blocking rule above would mean finding your own game asleep.
  • Sign-in: Google + email OTP (Gmail SMTP). No GitHub in v1, since it can return no email at all and there is then nothing to key an account on. Sessions 60 days, sign-out-everywhere included. Signup invite-only for now.
  • Two devices signed in at once is the one conflict left, and it is small: version-numbered writes, the stale device reloads.
  • Accepted risks, on the record: no backups (the DB is the only copy, so a disk failure ends every album), and a NAS outage blocks signed-in play.
  • Open questions: none. All ten are answered. What is left is the design pass plus a short list of values to supply (DDNS hostname, OAuth secret, Gmail app password).

Next step: write docs/cloud-sync-design.md. The client storage-adapter refactor inside it is shippable before any server exists.

04 More World Cups and collectibles Extend the dataset backwards from 1990: 1986, 1982, and earlier. Content ▸

The dataset covers 1990 to 2022 (all nine, fully researched). Collectibles grow for free, since collectibility is derived from rating via STICKER_TIERS with no lookup table.

  • Method notes from the 1990-2002 research round apply: identical name spellings across tournaments for the same person (personId is the name slug), distinct people must have distinct names, and ratings are that-tournament strength on the 60-99 scale.
  • Field sizes shrink going back (24 teams in 1982 and 1986, 16 in 1970 to 1978), so check the group draw and any "32 nations" assumptions first.
  • Period identities keep their own codes, as with Soviet Union, Czechoslovakia, and Yugoslavia already in the set.
  • Guards: npm run checks and the dev-time domain/validateSquads.ts.
